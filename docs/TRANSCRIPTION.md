## 位置づけ

- 本文転記は「原文層」として、知識単位（`src/data/knowledge/`）・正式問題（`src/data/questions/`）とは分離して保持する（判断の記録: docs/DECISIONS.md #16）。
- データ本体: `src/data/transcripts/<章ID>.json`（章別分割、全ファイル128KB未満を維持。第二章は容量のためバッチT11で `ch2-1.json`（p.52〜67）と `ch2-2.json`（p.68〜91）に章内分割し、バッチT12で `ch2-3.json`（p.92〜）を新設した。判断の記録: docs/DECISIONS.md #17）。バッチT14で第三章用に `ch3.json`（p.110〜）を新設した。バッチT17で検定情報用に `exam.json`（p.136〜）を新設した。集約モジュール: `src/data/transcripts.ts`（型定義・`TRANSCRIPT_PAGES`・`TRANSCRIPT_BY_PAGE`・`transcriptPagesForSection`・`imageIdForBookPage`）。
- リーダーは節に属する転記済みページをページ順に表示する。転記のない節は「まだ転記されていません」と明示し、推測で本文を補うことはしない。

## ページレコードの形式

| フィールド | 内容 |
|---|---|
| `bookPage` | 本書の印刷ページ番号（画像内の印刷番号を目視確認した値） |
| `imageId` | 出典の原本画像ID（例 `IMG_9581`。`src/data/source-manifest.json` に実在し欠落でないこと） |
| `chapterId` / `sectionId` | `src/data/structure.ts` の章・節ID |
| `status` | `"転記済み"` のみ（部分転記のページは作らない） |
| `blocks` | 構造化ブロックの配列（下記） |
| `unclear` | 不明瞭箇所の配列 `{location, note}`。なければ空配列 |
| `note` | ページ固有の事情（文のページまたぎ、写真の扱い等） |

ブロック種別: `heading`（`level`: 1=章タイトル級 / 2=節タイトル級 / 3=小見出し、`text`）、`paragraph`（`text`）、`table`（`caption`＋`rows`: セル文字列の二次元配列）、`column`（`title`＋`text`）、`note`（`text`。章扉のキャッチコピー等の付随テキスト）、`caption`（`text`。写真・図版のキャプション文）。

## 転記ルール

1. **原文のまま起こす**。要約・言い換え・現代仮名遣いへの変換・誤字の訂正をしない。数字の表記（半角/全角）も原文どおりとする。
2. **推測で補わない**。読み取れない文字・箇所は本文中に推測文字を置かず、当該箇所を含む文単位で読解を試みたうえで、それでも確定できない場合はその旨を `unclear` 配列に `location`（ページ内の位置）と `note`（読めなかった内容と理由）で記録する。不明瞭を含むページは `unclear` が空でない状態で登録し、リーダーにも表示される。
3. **構造を保つ**。見出し・本文段落・表・コラム・注記・写真キャプションをブロックとして区別する。段落内の改行（行折り返し）は連結し、段落の区切りはブロックの区切りとする。
4. **ページ番号は転記しない**。印刷ページ番号は `bookPage` フィールドにのみ保持する。
5. **転記対象外**: ページ側面の章タブ・柱などの造本体裁、キャプション文のない写真・イラスト（テキストが存在しないため）、見出し先頭のチェックマーク等の装飾記号。
6. **章扉のキャッチコピー**は `note` ブロックとして文字どおり記録する（例: p.6 の「スパイス＆ハーブの基本を知っておこう」）。
7. **文がページをまたぐ場合**は、各ページとも印刷されたとおりに転記し（途中で切れた文はそのまま）、`note` に継続関係を記録する。
8. **写真キャプションの配置**: レイアウト上の写真位置ではなく、本文の読み順に近い位置のブロックとして配置し、その旨を `note` に記録する。
9. 転記のつど、原本画像内の**印刷ページ番号を必ず目視確認**し、`bookPage` と画像ファイルの対応が実測対応（p.71以下は画像番号＝ページ＋9575、p.72以上は＋9576）と一致することを確認する。前提と異なる場合は転記を中止して報告する。
10. バッチ完了時に `TRANSCRIPT_META.transcribedPages` と `src/data/structure.ts` の該当節 `transcriptionStatus` を実データと一致させる（`tests/transcripts.test.ts` で固定）。
