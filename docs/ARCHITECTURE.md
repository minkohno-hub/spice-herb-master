# ARCHITECTURE

- 構成: React 19 + TypeScript + Vite 6 + vite-plugin-pwa。ルーティングは HashRouter（GitHub Pages の静的配信で 404 を避けるため。DECISIONS参照）。状態は localStorage ベースの軽量ストア（`src/domain/store.ts`、キー `spice-herb-master:v1`）。Dexie は使わない（データ量が小さく依存を減らすため）。
- レイヤー: `src/domain/`（純粋ロジック: types / normalize / grading / srs / validate / stats / store、UI非依存で単体テスト対象）、`src/data/`（structure=目次照合済み構造、questions、source-manifest.json）、`src/components/QuestionRunner.tsx`（全形式の回答・採点UI）、`src/App.tsx`（アプリシェル: ナビ＋ストア＋ルート定義のみ）、`src/screens/`（8画面: ホーム/演習/電子書籍/カード/模試/分析/検索/品質管理。バッチE1で App.tsx から分割し React.lazy でルート単位に遅延読み込み。DECISIONS #23）。
- データ分離: 教材データ（原文層・構造化知識層）と問題データは論理分離。すべての正式問題は知識単位経由で原文（manifest画像ID＋ページ）へ辿れる設計（`SourceRef`）。安定ID: 問題・知識単位は一度採番したら再利用しない（types/validate で担保する方針）。
- バンドル分割（バッチE1、DECISIONS #23）: データ集約モジュール（`src/data/knowledge.ts` / `formal-questions.ts` / `transcripts.ts` / `questions.ts`）の同期APIは不変（テスト・生成系が直接 import する）。アプリ側だけを分割する: (1) 画面は React.lazy でルート単位のチャンクに分離。(2) 初期画面（ホーム）と模試は件数しか使わないため、軽量サマリ `src/data/summary.ts`（`APP_DATA_SUMMARY`、実データとの一致は tests/summary.test.ts で固定）だけに依存する。(3) vite.config.ts の manualChunks でデータ種別チャンク（data-questions / data-knowledge / data-transcripts）と vendor（React系）を分離する。実測（E1）: 初期表示JSは単一チャンク 2,863.80kB（gzip 435.00kB）→ **273.14kB（gzip 88.40kB）**（index 5.46＋vendor 261.82＋Home 3.91＋summary/stats/srs 計1.95）。残りのチャンクは data-questions 1,632.92kB / data-knowledge 430.65kB / data-transcripts 387.26kB / structure 43.55kB / source-manifest 69.94kB / questions（サンプル等）5.70kB と画面別小チャンクで、最初のデータ画面への遷移時に種別単位で読み込まれる。章単位の動的 import（集約モジュールの非同期化）は未実施の残課題。
- 容量対策: 教材画像・全文は端末へ一括永続保存しない。PWA precache は全チャンクを含む（workbox glob は js/css/html/svg のみ、最大3MB。実測 E1: **27件 / 2,804.94KiB**、最大チャンク data-questions 1,632.92kB も上限未満）ため、分割後もオフラインで全機能が動く。教材データ本体は章・節単位JSONに分割済み（`src/data/knowledge/`・`src/data/questions/`・`src/data/transcripts/`）で、将来の章単位の動的 import 化は画面側の非同期読み込み化として拡張できる。
