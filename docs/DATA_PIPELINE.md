# DATA_PIPELINE — 教材取り込み工程

1. 原本: Google Drive フォルダ「スパイスハーブ検定」(id: 1O5DljjOWrTQM8UG_zPOkTXoMa_zKsxgX) の PNG 139件。インベントリは `data/source-manifest.json`（= `src/data/source-manifest.json`、全140エントリ: 実在139＋欠落1）。各エントリは元ファイル名・画像ID・Drive ID・サイズを持ち、**推定/確定ページ番号は照合まで null**（連番から断定しない）。
2. ページ順復元: ファイル名連番ではなく、画像内のページ番号・目次・見出しで照合する。照合済みアンカー: 目次 IMG_9577–9579、IMG_9645=p.70、IMG_9646=p.71、IMG_9648=p.72、IMG_9649=p.73、IMG_9715=p.139、IMG_9716=p.140。
3. 文字起こし工程（未実施・フェーズ2）: 画像品質評価→補正→読み取り→構造復元→表のセル復元→図中文字・脚注抽出→学名/数値/単位確認→原本照合→検証済みテキスト保存。各要素に検証状態（未処理/抽出済み/要確認/原文照合済み/不明瞭/欠落）を付与。自動抽出だけでは「原文照合済み」にしない。
4. 構造化: 原文層（忠実転記）と知識層（知識単位）を分離。知識単位から問題を生成し、出典は知識単位経由で原文位置へ必須記録。
5. 再実行可能性: manifest を起点に節単位で処理・再開できる設計。教材更新時は差分比較→影響問題の特定→再検証（validate テスト）を行う。
