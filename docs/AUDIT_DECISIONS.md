## 判断（AD）

- **AD-1（B-05是正方針）**: 記述式の自動採点は、要点充足率が 1.0 の場合でも自動判定の correct を断定しない（null とし、自己採点での確定を必須化する）。ratio=0（要点皆無）の correct=false は維持する。根拠: 監査指令 §7.3「正確に判断できない回答を断定的に採点してはいけない」。キーワード羅列の検出は行わず、判定の断定回避で是正する。
- **AD-2（A-02是正方針）**: 章扉3葉（IMG_9592／IMG_9626／IMG_9685）は、本書自身のページ付け（p.15注記が図鑑扉を p.51 と参照し、欠番 17／51／109 と一致）に基づき、ページ 17／51／109 として転記する。転記ページ数は 130 → 133 になる。
- **AD-3（E-06／E-07是正方針）**: Service Worker は `registerType: "autoUpdate"` に変更し、precache はアプリシェルに限定、データチャンクは runtime caching（CacheFirst）とする。確定仕様「必要な部分だけ取得／全文の恒久保存は原則不要」に合わせる。学習データは localStorage 側にあり SW と独立のため、履歴への影響はない。
- **AD-4（C-06）**: 模試の結果も SRS に反映する（演習と同じ quality 換算）。模試は本番形式の学習行為であり、間隔反復から外す理由がない。
- **AD-5（B-08是正方針）**: q4系（フェーズ4生成の四択）の誤答は、設問の次元（人物／成分／数量／地名／部位／書名／飲料 等）で型付けした同次元プールから再生成する。qsc系（プロフィール由来）は標本で良質だったため対象外。
- **AD-6（B-07是正方針）**: 別名の acceptedAnswers 展開は、照合済みプロフィール本文に「別名」として明記された語のみを機械展開する。推測による別名追加はしない。
- **AD-7（E-08是正方針）**: ci.yml は監査ブランチ上に GitHub Web UI から配置する（Muse GitHub App は workflows 配下を書けないため）。内容は ubuntu-24.04 固定・E2E ジョブ追加・npm audit ステップ追加に改訂する。
- **AD-8（E-01）**: npm audit は当VMのレジストリプロキシ制約で BLOCKED と記録する。「脆弱性なし」とは主張しない。CI に audit ステップを入れることで GitHub 側で継続照合する。
- **AD-9（B-03）**: 一問一答×四択のツイン329組は生成仕様上の意図的構成（想起／再認）としてデータを保持し、削除しない。体感的な近接出題の緩和は今後の課題として記録に留める。
- **AD-10（A-05）**: 写真は現行方針（DECISIONS #12、取り込み保留）を維持し、「収録範囲は本文テキストと表データ、写真はキャプション文のみ」であることを文書とUIに明示する。
